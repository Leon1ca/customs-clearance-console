# OCR、重复判断与金额合计

## 识别引擎（v1.5.3 起单引擎 + 规则复核）

v1.5.2 及以前，扫描件由 Tesseract 与 PP-OCRv5 各识别一遍再逐字段比对，每页要运行 Tesseract 三次（方向检测、整页、稀疏补扫）外加 PP-OCRv5 一次。v1.5.3 起只保留 **PP-OCRv5（RapidOCR / ONNX Runtime）**。选择它的原因：

- 它在中文表格单据上明显更准。以反馈关单为例，PP-OCRv5 单独识别即可正确读出全部字段。
- 它自带文字行方向分类，可以替代 Tesseract 的整页方向检测。
- 每页只需识别一次，速度明显快于双引擎。

流程：

1. PDF 有可靠文字层时直接读取文字与坐标，不做 OCR。
2. 扫描 PDF 按页渲染；图片支持 PNG、JPG/JPEG/JFIF、BMP、TIF/TIFF（含多页）、GIF、WEBP。GDI+ 无法解码的格式（如 WEBP）改用 OpenCV 解码。
3. 每页缩放到长边约 2800 像素后识别一次。页面方向：
   - 若多数文字框为竖长形，说明页面横放，再按 90° 与 270° 各识别一次；
   - 若多数文字行被方向分类器判为倒置，再按 180° 识别一次；
   - 保留最像关单的一次结果。
4. `DeclarationParser` 提取字段后，对 OCR 页面执行一致性规则，替代第二引擎：
   - **数量 × 单价 = 总价**：逐项核对（数量可取申报数量、法定数量或第二数量）。不符的分项不计入合计，关单标为“需关注”。
   - **报关单号**：表头最多印三处（预录入编号、海关编号、条码文字），任一处读出不同号码即标为“需关注”。
   - **目的国**：必须是国别表中的国家或地区；标签上的国别代码优先。
   - **出境关别**：必须是中文关区名称。框内值未读出时，取表头“海关编号”后括号里的关区名。
5. 旧版本保存的双引擎记录照常显示；导出中的“复核”列对新记录显示规则校验结论。

## 版面差异

- 识别前读取页面实际宽高，不依赖固定截图尺寸。
- PDF 有可靠文字层时优先使用原文字和坐标，避免不必要 OCR。
- 扫描件会按页面密度选择渲染/放大策略；页面方向和不同页边距由字段标签与相对坐标处理。
- 商品区以“单价/总价/币制”等表头和币制行作为锚点，支持多商品跨行累加。
- 严重裁切、模糊、印章完全遮挡或原图低分辨率造成的笔画丢失不可恢复；规则无法核对或核对不符时结果进入“需关注”。

## 重复判断

- 重复范围仅为本次所选文件夹中的列表。
- OCR 得到的 18 位报关单号相同，即视为同一份关单；文件名不参与判断。
- 同组所有记录置顶标红，便于用户检查来源文件。
- 去重时按字段完整度、置信度和异常状态选择一条规范记录；其余记录不再计入去重合计。

## 多币种金额

- 每个商品项目按“总价 + 币制”配对。
- 同一关单同币种金额求和；不同币种保持独立。
- 批次同时保留去重前和去重后字典，例如 `CNY`、`USD` 分别求和，不做汇率换算。
- 未识别币种的数字不会被擅自纳入某个币种。
