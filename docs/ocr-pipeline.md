# OCR、重复判断与金额合计

## 双引擎策略

软件不是把 Tesseract 与 PP-OCRv5 的全文拼接后再解析，而是维护两条独立链路：

1. 两个引擎分别输出带坐标与置信度的文字块。
2. `DeclarationParser` 对两份结果各自提取六个字段。
3. `DeclarationReconciler` 按字段类型比较：
   - 一致：直接通过。
   - 一方缺失、另一方满足严格格式：安全补全并保留说明。
   - 英文名称的极小字符差异：在高相似度与完整度条件下选择更完整结果。
   - 单号数字、合同号数字、金额或币种冲突：不自动猜测，标记“需关注”。

## 版面差异

- 识别前读取页面实际宽高，不依赖固定截图尺寸。
- PDF 有可靠文字层时优先使用原文字和坐标，避免不必要 OCR。
- 扫描件会按页面密度选择渲染/放大策略；页面方向和不同页边距由字段标签与相对坐标处理。
- 商品区以“单价/总价/币制”等表头和币制行作为锚点，支持多商品跨行累加。
- 严重裁切、模糊、印章完全遮挡或原图低分辨率造成的笔画丢失不可恢复，此时结果进入“需关注”。

## 重复判断

- 重复范围仅为本次所选文件夹中的列表。
- OCR 得到的 18 位报关单号相同，即视为同一份关单；文件名不参与判断。
- 同组所有记录置顶标红，便于用户检查来源文件。
- 去重时按字段完整度、置信度和异常状态选择一条规范记录；其余记录不再计入去重合计。

## 多币种金额

- 每个商品项目按“总价 + 币制”配对。
- 同一关单同币种金额求和；不同币种保持独立。
- 批次同时保留去重前和去重后字典，例如 `CNY`、`USD` 分别求和，不做汇率换算。
- 未识别币种的数字不会被擅自纳入某个币种。
