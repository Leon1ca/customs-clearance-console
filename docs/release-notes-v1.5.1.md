# 关单核验台 v1.5.1（UI v2 修正版）

日期：2026-09-24。Windows 10 / 11 x64 便携版：完整解压后双击根目录 `关单核验台.exe`，无需预装 .NET、Python 或 OCR。

本版修复 v1.5.0 真机测试反馈的问题；v1.5.0 的全部 UI v2 功能见 [v1.5.0 更新说明](release-notes-v1.5.0.md)。

## 网页长截图

- **官网查询页出现两张截图卡片、其中一张一直停在“截取中”**：官网的查询表单在一个与主页面同站的内嵌框架（swapp.singlewindow.cn）里，页面加载后才生成。原先卡片脚本在这个框架里也装了一张卡片；点这张卡片会开始截图，但进度和结果只回到主页面那张卡片，所以它会一直停在“截取中”。现在卡片只出现在主页面，查询点击的监听仍覆盖所有框架。
- **卡片收起后看不到失败原因**：收起的卡片收到截图结果（已保存、未保存及原因）时会自动展开，不会只剩“重试截图”。

## 高 DPI（125% / 150% 显示缩放）

- **根因**：各窗口在构造时开启了 WinForms 自动缩放，但此时窗口里还没有任何控件，结果只有窗口本身被放大，里面的控件仍是 100% 的位置和大小，而文字随系统缩放变大。于是在 150% 下：
  - 设置弹窗和分页文字被裁切（“每页”只剩“每”，“50 条”显示为“5..”）；
  - 标题栏只有 48 个物理像素，显得过窄；
  - 主窗口按 1440×900 放大到 2160×1350，超出 1920×1080 屏幕，右上角按钮跑到屏幕外。
- **修复**：所有窗口先按设计尺寸布局，窗口创建后按其实际 DPI 统一缩放一次，移到不同 DPI 的显示器时再缩放；圆角、分隔线、图标、关闭按钮等绘制也按实际 DPI 计算。
- 窗口按显示器可用区域摆放；设计尺寸放不下时（例如 1920×1080 的 150%）直接最大化打开。最大化不再盖住任务栏。

## 标题栏

- 标题栏右上角加入**最小化、最大化 / 还原、关闭**按钮。这些按钮以前会被挤到标题栏外，100% 下也看不到。现在的按钮与标题栏等高、46 像素宽，按 Windows 11 样式绘制：悬停时变亮，关闭按钮悬停时显示红色。

## 与设计稿对齐

- 表格：修复真实屏幕上每个单元格四周出现的灰色细线（抗锯齿设置从圆角标签泄漏到下一个单元格的底色填充，边缘只画了一半，露出未清空的缓冲区）；只保留行间分隔线，不画列竖线；表头 12.5px 中等字重、浅灰底、底部分隔线；金额显示为“USD 35,528.00”（币种在前）；“已留存”标签相机图标在前。
- 分页：当前页为深蓝底白字方块；无数据时为禁用样式。
- 搜索框：16px 搜索图标、13px 文字、控件描边色。
- “导出列表 | ⌄”“清理 ⌄”带下拉箭头。
- 设置弹窗：关闭按钮改为设计稿的“×”（悬停浅色圆底）；目录无效时提示具体是哪个路径不存在或无法访问。

## 验证

Windows GitHub Actions（`.github/workflows/windows-ui-v2.yml`）：
- 核心回归、构建、原生 UI 契约、导出校验、受控浏览器长截图 E2E、便携打包与干净解压冒烟测试。
- 浏览器 E2E 新增两项：
  - 仿官网的查询框架在页面加载后才生成时，截图卡片只能有一张（旧版这里有两张，测试失败）；
  - 收起的卡片收到拒绝结论后，必须显示原因。
- UI 快照在 **100% 和 150%** 两种显示缩放下各渲染全部 28 个状态、菜单与对话框，逐一断言：
  - 布局不越界；
  - 所有文字不被裁切（高度和宽度）；
  - 真实屏幕抓图中表格单元格边界没有灰色接缝。该检查每次运行会先故意复现旧问题，确认能检出后再检查正常绘制。

  150% 这一步是用 Windows 的显示缩放接口把测试机切到 150% 后真实渲染的，已纳入必需门禁。

## 已知边界

- 真实单一窗口验证码必须人工输入；CI 用受控页面模拟官网结构，真实网站全流程仍需人工验收。
- 若截图仍失败，卡片会显示原因；请同时提供 `%LocalAppData%\关单核验台\app.log`。
- 125% / 175% / 200% 与多显示器混合缩放未在 CI 中逐档渲染（逻辑与 150% 相同）；Windows 10 未实测。
